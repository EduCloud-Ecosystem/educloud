## Delivered boundary

The new test-only v7 slice uses the existing Broker, Store, journal, accounting,
watch and cleanup authority. A permanent assessment identity binds one exact
project, complete plan and scope. Every preplanned slot has immutable attempt
and reservation identities. Full reservation and definitive claim acknowledgement
precede any possible execution effect. A lost claim acknowledgement stays held;
reopening or looking up the claim cannot launch it again.

Workload and independent-checker phases run sequentially under one CPU allowance,
absolute deadline and combined output budget. The current private capability
accepts synthetic fixtures only. Actual sampling, reviewed installed Python/R
candidates, enforceable aggregate writable storage and faithful resource
collection require separate connected qualification. Unsupported measurements
remain null/unknown; conservative full charges are distinct from measured use.

Opaque operation owners track the original descriptor and lease acquisitions.
Shallow copies share one acquisition/launch/close result. Partial construction,
unlock and close errors remain uncertain, even when later metadata writes fail.
Only actual checked releases can publish ownership confirmation. Free leases,
PID death, full CPU settlement and imported receipts cannot supply that proof.
An orphaned attempt remains held and blocks later slots after conservative
settlement. A cancelled attempt whose original owner actually closes may settle
and permit only a different preplanned slot.

Known active ownership defers scope cleanup before claiming its cleanup epoch.
Cleanup uses the original immutable owner, actual file identity/removal, current
quiescence and checked closure. Synthetic `observed_absent` remains untrusted.
The test watcher is an in-process goroutine with real files/pipes, not a qualified
independent OS watcher or failure domain. No recovery mechanism reconstructs
opaque owners, retries uncertain effects or activates an old store.

A post-close metadata error is distinct from a physical close error. A committed
positive image can describe actual successful releases/removal despite loss of
the final journal acknowledgement. That original operation still returns held
and cannot retry or continue. A later distinct claim needs its own complete
fresh authority checks and definitive claim acknowledgement. No global durable
write-error fence, host durability guarantee or trusted cleanup is invented.

Raw input and output never enter ordinary retained Worker records, diagnostics,
sidecars, recovery copies or study exports. Supplied output writers retire when
Start returns, before transport shutdown; later callbacks refuse before changing
the output budget or capture. A final wipe follows transport teardown and clears
returned output on deferred error. This is bounded in-memory handling, not
cryptographic erasure or proof of swap, crash-report or backup exclusion.

Production prepare/ingest/seal/execute refuse from fixed command arguments before
stdin, state or provider effects. No runtime flag, environment variable, header,
claimed encryption, receipt or public capability factory enables them. Existing
v1/v2 codecs, ordinary defaults and AS1 identities remain unchanged. Fresh v7 has
no production initializer, migration, activation, checkpoint, restore or export.
